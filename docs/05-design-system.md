# Nayolites --- Design System

## 1. Design objective

The interface should communicate:

-   Trust
-   Institutional credibility
-   Professionalism
-   Simplicity
-   Competence
-   Calmness

It should not look like a generated SaaS template.

## 2. Visual character

Preferred:

-   Clean
-   Restrained
-   Modern
-   Institutional
-   High information clarity
-   Strong typography
-   Deliberate spacing
-   Subtle depth
-   Excellent forms and tables

Avoid visual novelty for its own sake.

## 3. Explicitly prohibited design patterns

Do not use:

-   Decorative gradients everywhere
-   Purple/blue AI-style gradients as the default identity
-   Glassmorphism
-   Floating blobs
-   Excessive rounded cards
-   Emoji as interface icons
-   Fake dashboard statistics
-   Huge marketing slogans with no informational value
-   Excessive animations
-   Confetti
-   Random icon styles
-   Inconsistent button shapes
-   Excessive shadows
-   Decorative UI that does not help the user complete a task

## 4. Typography

Typography should create clear hierarchy.

Use a professional, highly legible font stack.

Prioritize:

-   readable body text
-   clear page titles
-   compact table text
-   distinguishable labels
-   predictable heading hierarchy

Do not use oversized typography simply to imitate startup landing pages.

## 5. Color

Use a restrained institutional palette.

The final palette should be defined centrally through CSS
variables/design tokens.

Use color intentionally for:

-   brand
-   primary actions
-   success
-   warning
-   danger
-   informational states
-   neutral surfaces

Do not introduce arbitrary colors per component.

## 6. Spacing

Use a consistent spacing scale.

Components should feel related because their spacing follows the same
rules.

## 7. Components

Create reusable UI patterns for:

-   Buttons
-   Form controls
-   Inputs
-   Selects
-   Alerts
-   Badges/status indicators
-   Tables
-   Pagination
-   Breadcrumbs
-   Modal/dialog patterns
-   Navigation
-   Cards where genuinely useful
-   Empty states
-   Confirmation dialogs
-   File upload controls
-   Data filters

Do not create a card simply because the AI does not know how else to
present information.

## 8. Tables

Tables are important in the staff application.

They should support:

-   clear column headings
-   readable density
-   sorting where needed
-   filtering where useful
-   pagination
-   row actions
-   status indicators
-   responsive behavior

The table should make the work faster, not merely look attractive.

## 9. Forms

Forms should be treated as a first-class product surface.

Requirements:

-   clear labels
-   sensible grouping
-   required-field indication
-   server-side validation
-   useful error messages
-   preserved input on validation failure
-   clear save/cancel actions
-   confirmation for destructive or irreversible actions

## 10. States

Every important screen should consider:

-   Loading
-   Empty
-   Success
-   Validation error
-   Permission denied
-   Not found
-   System error

An empty state should explain what the user can do next where
appropriate.

## 11. Accessibility

Target strong baseline accessibility:

-   semantic HTML
-   keyboard navigation
-   visible focus states
-   adequate contrast
-   associated form labels
-   meaningful link/button text
-   accessible error messaging

## 12. Responsive behavior

The application must work on:

-   desktop
-   laptop
-   tablet
-   mobile

Staff workflows may prioritize desktop, but must not become unusable on
smaller screens.

## 13. Motion

Motion should be subtle and functional.

Use it to communicate:

-   transitions
-   feedback
-   state changes

Do not animate content merely to make the interface feel "AI-generated".

## 14. Brand authenticity

The college's actual identity should drive:

-   logo
-   imagery
-   typography
-   colors
-   institutional language

Do not fabricate institutional claims, statistics, accreditations,
rankings, testimonials, or achievements.

## 15. Product feel

The final product should feel closer to a well-designed professional
banking/education/operations application than a flashy startup template.

The goal is:

> Quiet confidence.
